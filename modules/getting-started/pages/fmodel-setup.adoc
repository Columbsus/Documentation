= Set Up FModel
:description: Configure FModel for PAYDAY 3 with the AES key and a current local mappings file.

https://fmodel.app/[FModel] is used throughout the PAYDAY 3 modding workflow to browse the installed game's Unreal Engine archives, inspect assets, and export files such as `AssetRegistry.bin`.

PAYDAY 3's archives are encrypted, and many of its Unreal Engine assets use unversioned properties. Because of that, FModel needs both the PAYDAY 3 AES key and a compatible mappings file before it can correctly read many assets.

== Install FModel

Download the current version of https://fmodel.app/[FModel] and launch it.

When FModel opens, select your PAYDAY 3 installation. If the game is not detected automatically, create an undetected game entry and point FModel at the game's archive directory, normally the `PAYDAY3/Content/Paks` directory inside the PAYDAY 3 installation.

[NOTE]
====
FModel's interface can change between releases, but the important settings are the game archive directory, AES key, Unreal Engine version, and local mapping file.
====

== Add the PAYDAY 3 AES key

PAYDAY 3's game archives require the following AES key:

[source,text]
----
0x27DFBADBB537388ACDE27A7C5F3EBC3721AF0AE0A7602D2D7F8A16548F37D394
----

In FModel:

. Open *Directory > AES*.
. Enter the PAYDAY 3 AES key shown above as the main encryption key.
. Save or confirm the AES configuration.
. Reload the PAYDAY 3 archives if FModel does not refresh them automatically.

Once the key is accepted, the encrypted game archives should become readable.

== Get a mappings file

FModel also needs a current Unreal mappings file, normally a `.usmap` file, to deserialize many PAYDAY 3 assets correctly.

The recommended option is to use the mappings file provided with the current PAYDAY 3 modkit release. Check the *Releases* section of the modkit repository and download the mappings file that matches the current game/modkit version.

If a current mappings file is not available, you can generate one from the game using a compatible dumper such as:

* https://github.com/Encryqed/Dumper-7[Dumper-7]
* https://github.com/UE4SS-RE/RE-UE4SS[UE4SS]

[IMPORTANT]
====
Mappings are version-sensitive. PAYDAY 3 updates can change reflected classes, structs, enums, and properties.

After a game update, use a mappings file generated for the updated game version. An old mappings file may cause missing properties, incorrect data, or package parsing errors.
====

== Configure FModel to use the local mappings file

After obtaining the `.usmap` file:

. Open *Settings* in FModel.
. Open the *General* settings page.
. Find *Local Mapping File (drag & drop)*.
. Enable the *Local Mapping File* option.
. Set *Mapping File Path* to the downloaded or generated `.usmap` file. You can use the browse button next to the path field, or drag the mapping file into FModel where supported.
. Save the settings.
. Reload the PAYDAY 3 archives if necessary.

FModel's current settings expose both the *Local Mapping File (drag & drop)* toggle and a *Mapping File Path* field when the local mapping option is enabled.

== Why the mappings file is required

Many PAYDAY 3 packages contain unversioned Unreal properties. The package data does not contain enough information by itself for a generic asset reader to reconstruct every property layout.

The mappings file supplies the schema FModel needs for PAYDAY 3 classes, structs, enums, and their properties.

Without a compatible mappings file, FModel may still list archives and some files, but many assets cannot be fully parsed or inspected. You may see errors about a missing mapping file or unversioned properties, and exported/inspected asset data can be incomplete.

This is why the mappings file is required for common workflows such as:

* Inspecting Blueprint and data asset properties.
* Reading reflected class and struct data.
* Examining references inside many cooked packages.
* Exporting or inspecting assets that depend on unversioned property layouts.
* Locating and extracting files needed by the modkit setup workflow.

== Verify the setup

After configuring the archive directory, AES key, and local mappings file:

. Reload the PAYDAY 3 archives.
. Browse into the game's packages.
. Open a few Blueprint or data asset packages.
. Confirm that FModel displays their properties without mapping-related errors.

If FModel can list the archives but fails to deserialize many assets, first check that the local mapping option is enabled and that the selected `.usmap` matches your installed PAYDAY 3 version.

== FModel mappings and the modkit JMAP are different

Do not confuse the FModel `.usmap` mappings file with the JMAP generated for the PAYDAY 3 modkit.

* The `.usmap` file is used by tools such as FModel to understand Unreal Engine property layouts.
* The modkit JMAP is generated locally after installing the modkit by running `GenerateJMAP.bat` with the current game's `AssetRegistry.bin`.

The modkit does not ship with the generated JMAP. The next step explains how to extract `AssetRegistry.bin` with the FModel setup you have just configured and generate it locally.
